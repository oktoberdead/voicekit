# VoiceKit

Локальный процессор голоса для **Windows 11 + VB-CABLE**. C# / .NET 10, WPF, WASAPI/NAudio. Без нейросетей, облака и аккаунтов. Есть опциональный веб-пульт для телефона в домашней сети.

**Статус: первая экспериментальная реализация, не готовая замена Voicemod.** Есть аудиодвижок, DSP, настройки и управление; качество эффектов, реальные задержки и совместимость с USB-устройствами необходимо проверить на Windows. Для Windows-сборки и тестов подготовлен шаблон CI, но при первоначальной разработке в Linux-среде без доступного SDK их выполнить не удалось. Разбор C#/XAML не заменяет компиляцию.

## Что реализовано

- Физический микрофон → цепочка эффектов → микшер → выбранный выход (обычно **CABLE Input**).
- **Питч ±12 полутонов:** STFT phase vocoder, окно 1024 сэмпла, перекрытие 4×. Без сохранения формант.
- **Воббл питча:** синусоидальный добавочный сдвиг между двумя границами −12…+12 полутонов, частота 0.1–12 Гц.
- **Робот:** кольцевая модуляция с частотой и wet/dry.
- **20-полосный вокодер:** синтезаторная несущая (тон/мажорный аккорд) или MP3/WAV; уровень, повтор, перезапуск/продолжение позиции при включении.
- **Эхо:** время, обратная связь, уровень. **Реверберация:** сеть comb/all-pass, затухание, уровень.
- Отдельное прослушивание обработанного голоса, саундпада и чистого микрофона. Мониторинг **не меняет** передачу в кабель.
- Пресеты эффектов и файловой несущей, пользовательские глобальные клавиатурные хоткеи.
- **Веб-пульт:** пять эффектов (без вокодера), кнопка включения + раскрываемые слайдеры, синхронизация с ПК, сопряжение по коду.
- Саундпад: локальная библиотека со стабильными ID, до 32 одновременно играющих звуков, удержание/тоггл/одиночный запуск, повтор, ignore/restart/overlap.
- Раздельные уровни, mute микрофона, остановка саундпада, **фиксируемый PANIC**, трей и сохранение настроек.
- Ограниченные очереди, адаптивная коррекция дрейфа часов, счётчики сбоев и диагностика нагрузки DSP.

Пока **нет** редактора мобильных раскладок/вкладок, саундпада в веб-пульте, плагинов VST, автозапуска с Windows, нейрообработки, изменения формант, шумоподавления/AEC, MIDI и кнопок мыши. Сетевой порт открывается **только после явного включения веб-пульта**.

## Сборка

На Windows установи **.NET 10 SDK x64** (именно SDK, не только Runtime). Visual Studio не обязателен. Все команды ниже выполняются в корне репозитория, в PowerShell:

```powershell
dotnet build VoiceKit.slnx -c Release
```

Первый вызов автоматически восстанавливает NuGet-пакеты, поэтому требуется интернет. SDK должен быть версии 10.0.100 или новее в ветке 10.0. Если `dotnet` не найден, перезапусти терминал после установки SDK.

Запуск:

```powershell
dotnet run --project src/VoiceKit.Windows -c Release
```

Либо запусти `src\VoiceKit.Windows\bin\Release\net10.0-windows\VoiceKit.exe`.

Тесты DSP, буферов и саундпада (работают также на Linux/macOS с .NET 10):

```powershell
dotnet test tests/VoiceKit.Core.Tests -c Release
```

Самодостаточная папка приложения, которую можно переносить на другой Windows x64 **без установленного .NET**:

```powershell
dotnet publish src/VoiceKit.Windows -c Release -r win-x64 --self-contained true -o artifacts/VoiceKit
```

Запускать `artifacts\VoiceKit\VoiceKit.exe`; переносить **всю папку**, не один exe. VB-CABLE устанавливается отдельно. Шаблон CI `docs/ci/build.yml` описывает сборку Windows-приложения, запуск тестов и сохранение такой папки как artifact; проверка устройств в CI невозможна. Сейчас workflow **не активен**: подключению Arena не хватает права `workflows`. Для включения скопируй шаблон в `.github/workflows/build.yml` и отправь изменение через своё подключение с нужными правами либо создай этот файл в веб-интерфейсе GitHub.

## Первый запуск — безопасная маршрутизация

1. Подключи USB-гарнитуру и убедись, что VB-CABLE установлен. Для старта выставь **48 кГц** у устройств в панели звука Windows, если формат доступен. Отключи эксклюзивный захват другими программами при проблемах открытия.
2. Разреши настольным приложениям доступ к микрофону: *Параметры → Конфиденциальность и безопасность → Микрофон*.
3. На вкладке **Маршруты** выбери:
   - микрофон: физический микрофон USB-гарнитуры;
   - передача: **CABLE Input (VB-Audio Virtual Cable)**;
   - прослушивание: USB-наушники (либо «Не использовать»).
4. Начни с буфера **30 мс**, выключенных эффектов и выключенного мониторинга голоса. Нажми **Запустить аудио**.
5. В Discord/игре/OBS выбери вход **CABLE Output**, а обычный выход оставь на наушниках.
6. Для проверки включи только **Слушать обработанный голос**, затем пробуй эффекты по одному. Уровни начинай с небольших значений.
7. Сначала проверь запись в обычном диктофоне/OBS без его дополнительного мониторинга. Шумоподавление, AGC и echo cancellation Discord могут изменять/вырезать эффекты и музыку; для сравнения отключи их.

**Не включай Windows «Прослушивать с данного устройства» и второй мониторинг того же сигнала в OBS.** Это независимые обходные маршруты; приложение не может их выключить за тебя. Не выводи мониторинг в тот же кабель. Входы с `CABLE` в названии запрещены как микрофон для защиты от очевидной петли. Переименованный кабель или более сложную внешнюю петлю автоматически распознать нельзя.

Мониторинг через колонки опасен обратной связью. Чистый и обработанный голос одновременно дают двоение/фазовую окраску — чистый монитор предназначен для отладки. Bluetooth добавляет задержку, для оперативного прослушивания лучше USB/провод.

Изменение устройств и размера буфера применяется при **остановке и новом запуске**. Приложение не начинает передачу само при запуске и не выбирает колонки вместо пропавшего устройства.

## Веб-пульт на телефоне

1. Пересобери и запусти приложение. Во вкладке **Телефон** нажми **Включить веб-пульт** (по умолчанию порт `8765`).
2. Если появится запрос брандмауэра Windows — разреши VoiceKit **только в частных сетях**. Запуск администратором не нужен.
3. Подключи телефон к той же домашней сети и открой в браузере адрес из приложения, например `http://192.168.1.20:8765/`. Если адресов несколько, выбери Wi-Fi/Ethernet той сети, не VPN. Не вводи `localhost` на телефоне: это адрес самого телефона.
4. Введи восьмизначный код со вкладки **Телефон**.
5. **Верх карточки** включает/выключает эффект. **Нижняя полоска «Параметры»** раскрывает слайдеры и не переключает эффект. Можно включать несколько эффектов одновременно.

Доступны **питч, робот, эхо, реверберация и воббл питча**. Вокодер не меняется веб-командами. Аудио и устройства остаются на ПК, телефон не запрашивает разрешение на микрофон. Аудиодвижок запускается отдельно в Windows-панели.

Изменения телефона отражаются на ПК; изменения на ПК/хоткеями подтягиваются в браузер примерно раз в 800 мс. Движения слайдеров отправляются с ограничением частоты, с последним актуальным значением. При потере связи кнопки блокируются, неотправленные команды сбрасываются, а после восстановления сначала читается реальное состояние. Изменение эффектов **не снимает PANIC**, mute или общий bypass: они показаны предупреждением.

Код и сессии живут до выключения веб-пульта. Остановить и снова включить его — способ отключить все телефоны. Пульт работает и при скрытом в трей приложении, но не запускается автоматически после перезапуска VoiceKit. Код не сохраняется в настройках, токен браузера хранится в `sessionStorage`.

**HTTP без шифрования — только для доверенной домашней сети.** Код сопряжения не заменяет TLS. Не открывай порт на роутере, не публикуй через внешний туннель и не разрешай доступ из публичных сетей. Подробнее: [веб-пульт и его API](docs/WEB-REMOTE.md).

Для Windows-сборки **Node.js и npm не нужны**: HTML/CSS/JS встроены в DLL через MSBuild. При self-contained publish серверный ASP.NET Core runtime включается в общую папку. Для framework-dependent запуска нужны .NET 10 Desktop и ASP.NET Core runtime; установка полного .NET 10 SDK покрывает разработку.

## Управление

| Хоткей по умолчанию | Действие |
| --- | --- |
| `Ctrl+Alt+F1` | Mute микрофона, включая его хвосты эффектов |
| `Ctrl+Alt+F2` | Включить/обойти всю цепочку эффектов |
| `Ctrl+Alt+F3` | Прослушивание обработанного голоса |
| `Ctrl+Alt+F4` | Остановить все звуки саундпада |
| `Ctrl+Alt+F5` | Запустить/остановить аудиодвижок |
| `Ctrl+Alt+F12` | **PANIC: заглушить весь выход и мониторинг** |

Хоткеи редактируются на вкладке **Пресеты и хоткеи**, затем нужно нажать **Применить хоткеи**. Звуки и пресеты имеют собственное поле хоткея. Примеры: `F13`, `Ctrl+Alt+1`, `Shift+NumPad3`. Пустое поле отключает привязку. Внутренние дубликаты отклоняются, старые назначения при ошибке сохраняются.

Keyboard hook подавляет обработанные нажатия, autorepeat и отпускания. Это **не гарантия приоритета** перед другим hook, Raw Input, процессом с повышенными правами или античитом. Не назначай важные системные сочетания и не запускай приложение администратором без необходимости. Пока нет автоматического обнаружения конфликта с чужими хоткеями и watchdog переустановки hook, если Windows сняла его по таймауту UI.

**PANIC защёлкивается**: изменение настроек не вернёт звук. Для сброса останови и запусти аудиодвижок заново; создастся чистый граф без старых хвостов. Уже переданные драйверу сэмплы нельзя отозвать — физическая тишина наступит после существующих выходных буферов. Mute плавный, PANIC намеренно немедленный на стороне нашего графа.

Крестик окна прячет его в трей (если значок успешно создан). Двойной клик по значку открывает окно, правый клик — меню. **Выход** действительно завершает приложение. Одновременно разрешён один экземпляр на пользовательскую сессию.

## Вокодер с MP3

1. На вкладке **Эффекты** выбери в вокодере источник **Аудиофайл**.
2. Нажми **Выбрать MP3 / WAV…**, настрой уровень и повтор.
3. Включи вокодер и говори в микрофон.

Речь управляет огибающими полос, файл даёт несущую. Это «говорящая музыка», **не перенос вокала и не автопение твоим голосом**. Без речи или без загруженного файла результат будет тишиной после короткого перехода. Файлы с широким спектром (синтезаторные аккорды, насыщенная музыка) обычно разборчивее тихих/басовых фрагментов.

Несущая не добавляется напрямую к передаваемому звуку. Для фоновой музыки используй саундпад. Выключение вокодера приостанавливает файловую позицию; повторное включение либо сбрасывает её, либо продолжает, согласно флажку. После конца файла без loop для повторного старта включи «начинать сначала» и переключи вокодер. После перезапуска двигателя позиция всегда начинается заново.

## Воббл питча

В Windows-панели — секция **Воббл питча**, на телефоне — пятая карточка **Воббл**. Это изменение высоты тона, не амплитудный перегруз/distortion.

- **Нижняя / верхняя граница:** добавочный сдвиг в полутонах, каждая в диапазоне −12…+12.
- **Частота:** 0.1–12 Гц (полных колебаний в секунду), синусоидальная форма.
- **По умолчанию:** выключен, границы −2…+2, частота 3 Гц. Старые настройки/пресеты тоже загружаются с выключенным вобблом.
- **С обычным питчем:** сдвиги складываются. Питч +3 и воббл −2…+2 дают диапазон +1…+5. Выключенный обычный питч не добавляет свой сохранённый сдвиг.
- **Равные границы:** постоянный добавочный сдвиг; обе границы 0 — нет модуляции. При пересечении ползунков соседняя граница подтягивается, диапазон остаётся корректным.

Параметры, вкл/выкл и частота сглаживаются; после изменения им требуется короткое время для установления. На каждом пересечении нуля **не происходит переключения на чистый микрофон**. Воббл использует тот же STFT-питчер: второго этапа FFT или дополнительной очереди нет. Если обычный питч был обойдён, включение воббла вводит задержку самого pitch-этапа (около одного STFT-окна), то есть это не zero-latency. Неизменность общей нагрузки/сквозной задержки не гарантируется — измерения всё равно нужны. При больших размахах и высокой частоте возможны выраженные фазовые/«металлические» артефакты; для начала попробуй ±0.5…1 полутон и 3–5 Гц.

Монотонный F0/autotune, независимые форманты и пресет феминизации **ещё не реализованы**. Они требуют отдельной работы над DSP; повышение питча само по себе не обеспечивает естественное изменение воспринимаемого гендера голоса.

## Саундпад

Импорт копирует файл в управляемую библиотеку; кнопка ссылается на GUID. Изменение исходного файла после импорта не меняет библиотеку. Импортированный звук выбирается слева, его название, поведение и хоткей сохраняются кнопкой **Применить к звуку**.

- **Однократно**: запуск по нажатию; с флажком loop играет до остановки.
- **Удержание**: запуск на key-down, плавная остановка на key-up; loop независим.
- **Тоггл**: второе нажатие останавливает активный звук.
- **Повторное нажатие**: игнорировать до конца, начать заново, добавить ещё один экземпляр. Тоггл имеет приоритет над этой настройкой.

Разные звуки могут играть вместе. При достижении 32 голосов новые запускаемые экземпляры отклоняются (счётчик в диагностике). Кнопка мыши поддерживает удержание; при потере mouse capture звук отпускается. Клавиатурная активация экранной кнопки удержания не используется — назначь глобальный хоткей.

Файлы декодируются вне аудиопотока в моно 48 кГц и хранятся в памяти. **Максимум 5 минут на файл и 384 МиБ загруженных сэмплов** суммарно с несущей; временная память во время декодирования может быть выше. Длинные фоновые треки со streaming, стереопространство и бесшовные loop-точки — будущая работа. Края файлов кратко сглаживаются, что уменьшает щелчки, но может быть слышно на цикле.

## Стабильность и задержка

- Выход передачи задаёт темп DSP. Обработка выполняется **один раз**; наушники читают отдельную очередь, а не гонят ещё одну копию эффектов.
- Capture и мониторинг используют ограниченные SPSC-буферы. Медленная occupancy-коррекция ресемплинга компенсирует небольшой дрейф независимых часов.
- Большое отставание вызывает consumer-side resync, а не бесконечное накопление задержки. После переполнения старые данные отбрасываются полностью. Это аварийная мера, не нормальный рабочий режим.
- Недостаток данных даёт затухание в тишину и повторное заполнение, а не повтор последнего блока в цикле.
- В собственном DSP нет IO, блокировок и выделений памяти на блок/сэмпл; NAudio, драйвер и среда .NET сами по себе не дают гарантий hard real-time.
- Обратная связь ограничена, уровни сглаживаются. На обоих выходах мягкое насыщение с пределом около 0.99, **не студийный lookahead-лимитер**. Оно не заменяет правильный gain staging.
- При сообщённой WASAPI ошибке и при сне Windows тракт останавливается. Восстановление **ручное**: переподключить устройство, обновить список при необходимости, запустить аудио. Автопереподключения пока нет.

Показания очередей **не являются полной end-to-end задержкой**. В неё также входят USB/драйверы, WASAPI, VB-CABLE, окно питча, принимающая программа и мониторинг. Начальный буфер 30 мс — консервативная настройка, не обещание задержки 30 мс. При стабильной работе можно пробовать 20/15 мс; при треске — 50/80 мс. Общий тракт shared-mode; exclusive/ASIO пока нет. Адаптивный ресемплер линейный, не высококачественный band-limited SRC; одинаковый формат 48 кГц предпочтителен.

Смотри [план проверки на Windows](docs/WINDOWS-TESTING.md) и [архитектуру](docs/ARCHITECTURE.md).

## Данные

`%LOCALAPPDATA%\VoiceKit\`:

- `settings.json` — устройства, параметры, пресеты и привязки;
- `settings.json.bak` — предыдущая версия после атомарной замены;
- `settings.json.invalid-*` — копия повреждённых/несовместимых настроек;
- `Library\` — импортированные аудиофайлы и несущие.

Текущие аудиопараметры сохраняются с задержкой 700 мс после изменения. Поля звука/пресета/хоткеев требуют своей кнопки применения. Смена маршрутов сохраняется при сохранении, старте аудио или выходе. Удаление звука удаляет его управляемую копию, если на неё не ссылается пресет/несущая; **оригинал пользователя не трогается**. Неиспользуемые старые файлы несущей автоматически не очищаются, чтобы не разрушить ссылки пресетов. Пользовательские данные не помещаются в Git.
