# Проверка на Windows 11

Пока это **план ручной приёмки**, а не отчёт о прошедших hardware-тестах. Начинай с низкой громкости в наушниках. Не тестируй обратную связь через колонки.

## 1. Сборка и автоматические тесты

```powershell
dotnet --info
dotnet build VoiceKit.slnx -c Release
dotnet test tests/VoiceKit.Core.Tests -c Release --logger trx
```

Сохрани ошибки полностью, вместе с `dotnet --info`. Убедись, что выбран .NET 10 SDK, не Preview 11 и не Runtime без SDK. Для ручных проверок используй Release, не debugger.

## 2. Базовая маршрутизация

- USB микрофон → CABLE Input, наушники → monitor, принимающая программа → CABLE Output.
- Выключить все эффекты, monitoring Windows/OBS и обработки принимающей программы.
- Записать речь. Проверить, что нет двух копий голоса, эха и внезапных всплесков.
- Включать dry/processed monitor по одному: передаваемая запись не должна изменяться.
- Выключить monitor device целиком: передача должна продолжаться.
- Проверить mute микрофона: саундпад остаётся, голос и его хвосты исчезают с коротким сглаживанием.

## 3. Эффекты

- Питч: −12, −5, 0, +5, +12. При 0 должен быть прямой сигнал без постоянной подмешанной задержанной копии.
- Робот: 40–200 Гц, wet/dry. Отсутствие сильных щелчков при переключении.
- Вокодер: синтезатор, затем файл; без речи не должно быть постоянно звучащей несущей.
- Файл: loop, конец без loop, restart и pause/resume. Проверить разные MP3 sample rates и stereo WAV.
- Эхо: большие delay и feedback; выключение send оставляет затухание. Reverb — аналогично.
- Все эффекты вместе: смотреть DSP budget, уровень и стабильность. Снижай входной gain, если защита выхода слышимо искажает сигнал.
- Пресеты: переключение хоткеем, сохранение/перезапуск приложения, ссылка на файловую несущую.

## 4. Саундпад и хоткеи

- Одиночный запуск, ignore/restart/overlap, toggle, hold с loop и без.
- Два разных звука вместе; 33+ голосов: ограничение, без падения.
- Удерживать кнопку, отпустить вне окна/после смены фокуса: звук должен остановиться.
- Удерживать хоткей, отпустить сначала модификатор, затем основную клавишу: звук должен остановиться.
- Autorepeat не должен запускать копии без новых нажатий.
- Проверить stop-all и PANIC во время loop, эха и музыки. После PANIC менять настройки: звук не должен вернуться.
- Изменить хоткеи, назначить дубликат: показать ошибку и оставить старые работающими.
- В целевых играх проверить подавление отдельно. Если игра игнорирует hook, это не повод пытаться обходить античит.

## 5. Накопление задержки

На i3-13100F + USB-гарнитуре: 30 мс, затем при стабильности 20/15 мс. Продолжительность каждого полноценного прогона **30–60 минут**.

- Записать очереди, drift ppm, underrun/resync, DSP/budget в начале и каждые 10 минут.
- Включить/выключить monitor во время работы. Если доступны — попробовать наушники и микрофон от разных USB-устройств.
- Добавить нагрузку CPU обычной игрой/компиляцией. Счётчики сбоев могут вырасти под перегрузкой, но после её снятия очередь должна вернуться к рабочему уровню, а не доигрывать историю.
- Паузы и длину эха не путать с накоплением latency.
- Для измерения сквозной задержки записать два синхронных пути одного тестового импульса/сигнала на двух каналах в DAW и сравнить корреляцию до/после. Измерять отдельно dry transmit и monitoring с эффектами. Размер буфера в UI не считать результатом измерения.

## 6. Сбои и жизненный цикл

- Отключить USB-гарнитуру во время работы. Ошибка/остановка без автопереключения на колонки. Переподключить, обновить устройства, заново запустить.
- Сон/пробуждение Windows: остаётся остановленным до явного запуска; старый звук не проигрывается.
- Смена устройства по умолчанию Windows не должна перенаправлять явно выбранные endpoints.
- Несколько циклов start/stop; закрытие в трей; перезапуск Explorer (значок должен восстановиться); выход через меню.
- Второй экземпляр не должен захватывать устройства/перезаписывать настройки.
- Удалить/переименовать копию файла в Library при закрытом приложении: при запуске понятное сообщение, другие файлы доступны.
- Повреждённый JSON: резервная копия `.invalid-*`, безопасные начальные параметры, двигатель не стартует автоматически.

## Что прислать при проблеме

Версия Windows и .NET, названия/частоты устройств, размер буфера, используемые эффекты, что записывает CABLE Output и что слышно в наушниках, скрин диагностики до и после. Не присылай приватные аудиофайлы, если проблема воспроизводится на тестовом сигнале.
