# Лаборатория голоса — экспериментальная калибровка

Это первый этап персонального подбора, не автоматическая феминизация. Он позволяет сравнить обработку на **одной записи**, а не на по-разному произнесённых фразах. Независимые форманты, pitch correction к одной ноте, адаптивная обработка тембра, EQ/компрессор и слепое A/B пока **не добавлены**.

## Изоляция от обычного режима

- Открытие кнопкой в верхней панели главного окна. Нужны выбранные физический микрофон и отдельный выход прослушивания.
- При работающем основном движке перед остановкой запрашивается подтверждение. Он останавливается целиком, не перенаправляется на лабораторию.
- Capture стартует только кнопкой «Записать» внутри лаборатории. Пока ты просто читаешь инструкции/смотришь измерения, микрофон лабораторией не захватывается.
- Веб-пульт не получает запись и не имеет API для запуска лаборатории. Если им менять живые эффекты во время лаборатории, они не меняют зафиксированные A/B; последующее явное «Применить» заменит эффекты выбранным вариантом.
- Весь playback идёт в отдельно проверенный endpoint наушников; выбор ID выхода передачи или имени с CABLE отвергается. Переименованный виртуальный кабель автоматически распознать нельзя — проверяй маршрутизацию.
- Основные хоткеи (включая mute и start/stop) на время модального окна приостановлены. PANIC действует на запись/прослушивание/расчёт лаборатории. После него воспроизведение возможно только по новому явному нажатию; автоматического возобновления нет.
- При сне или сбое устройства лаборатория останавливается без подмены устройства. После любого закрытия основной двигатель нужно запустить вручную.
- Windows monitoring, аппаратный sidetone гарнитуры и другие программы, захватывающие физический микрофон, вне контроля VoiceKit. Используй наушники, не колонки.

## Материал и измерения

Сценарий v1 длится 38 с. Отсчёт идёт по числу записанных сэмплов, не по таймеру интерфейса: тишина 0–3, «а» 3–6, «и» 6–9, «у» 9–12, фраза 12–26, свободная речь 26–38. Указанная фраза — удобный пример, **не стандартизированный фонетический тест**. Проверки того, что произнесён именно указанный текст, нет.

Многоканальный вход усредняется в mono; показатели уровня/предела относятся к этому моносигналу, а не каждому аппаратному каналу отдельно.

Чистый здесь означает «до эффектов/усиления/mute VoiceKit». Обработки USB-гарнитуры и Windows могут уже присутствовать. Важно записывать обычный голос с привычной дистанции. На время первых 3 секунд действительно молчи: иначе речь будет принята за высокий фон и рекомендация может стать недоступна.

Анализ показывает:

- пик, речевой RMS после первых 3 секунд, RMS фона;
- число моно-сэмплов с амплитудой ≥0.999 (близость к пределу, не доказательство именно аппаратного clipping);
- медиану F0, 10-й/90-й перцентили;
- приблизительную длительность/долю кадров, где найдена периодичность, и её оценку;
- ограничения качества и предупреждения.

F0: offline YIN-подобная разностная функция после low-pass/decimation до 12 кГц, окна 64 мс, шаг 20 мс, поиск 60–500 Гц. Это не добавляет задержку живому аудио — анализ идёт после записи. Обработка может занять несколько секунд, UI остаётся доступен для отмены/PANIC/закрытия. Ошибки на октаву, хрипе, шёпоте, фоне и переходах всё ещё возможны. Периодичность **не равна вероятности правильного результата**.

Для предложения питча нужны минимум 2 с тональных кадров, допустимый уровень сигнала, отсутствие некорректных сэмплов, меньше 0.1% сэмплов около предела и разброс P10–P90 не больше октавы. Эти эвристики консервативны и требуют проверки на реальных голосах. Ручной выбор остаётся доступен, даже если рекомендации нет.

Предложение: `12 × log2(желаемая_медиана / измеренная_медиана)`, ограничение ±12 полутонов, округление 0.1. Цель выбирает человек (80–350 Гц); приложение не назначает диапазон по полу и не «оценивает женственность». Это **статический сдвиг**, не выравнивание интонации. Вокодер, робот и воббл могут сделать такую прикидку нерелевантной — для первого подбора удобны нейтральный A и «только питч» B.

## Сравнение

A — снимок эффектов при открытии окна (или нейтральный вариант по флажку). B — этот же набор с редактируемым питчем, либо только питч по флажку. На время «Подготовить A/B» параметры фиксируются; после изменения требуется новый расчёт. Выбирается фраза, свободная речь, гласные или вся речь. Если запись короткая, используй «Вся речь»; отсутствующие фрагменты отклоняются.

Два новых `VoiceProcessor` обрабатывают одинаковый материал с одинаковой начальной временной точки. Саундпад, gain/mute основного микшера и устройства передачи не участвуют. Применяется защитное насыщение как у графа, затем ограничение пиков для наушников. Это сравнение **эффектов**, а не точная копия уровня живого выходного микшера.

Для прослушивания можно приблизительно подровнять общий RMS к −20 dBFS. Усиление ограничено ×4, пики — 0.9; почти тишина не усиливается. Для сильно различающихся динамики/спектров одинаковый RMS не означает одинаковую воспринимаемую громкость. Нормализация не меняет исходник и не попадает в применяемый пресет.

Оригинал/A/B читаются одним provider'ом с общей позицией и короткими кроссфейдами. Речь не начинается сначала при переключении. Разные эффекты могут иметь разную алгоритмическую задержку: одинаковые индексы **не гарантируют фазовое совпадение**, на переходе возможна краткая окраска. Стоп → Play начинает фрагмент заново. Хвост в конце выбранного фрагмента обрезается со сглаживанием границы.

## Данные и обратимость

Только явное «Сохранить профиль + WAV» пишет `%LOCALAPPDATA%\VoiceKit\Calibration\<GUID>\sample.wav` и `profile.json`. WAV — mono float32 / 48 кГц, максимум 38 с (~7.3 МБ). JSON содержит версию сценария, название, время, устройство записи, A/B-настройки, цель, выбор и отчёт; не модель голоса. Токены/сетевые данные не сохраняются.

Каждое сохранение создаёт **новую** папку и не перезаписывает старые профили. На открытии отчёт пересчитывается из WAV. При отмене сохранения временная папка удаляется; после аварийного завершения процесса может остаться `.pending-*`, её можно удалить вручную. Неподдерживаемые схемы и повреждённые/слишком большие файлы отвергаются.

Файл несущей вокодера не входит в профиль. Хранится только идентификатор управляемого файла; JSON не используется как произвольный путь. Для файлового вокодера потребуется та же уже загруженная несущая при открытии лаборатории. Если её нет, можно выбрать нейтральный A и только питч B для сравнения.

Закрытие без применения не меняет живые эффекты и не сохраняет запись. «Применить» добавляет обычный пресет с выбранными эффектами и применяет их, но не сохраняет WAV; маршруты, mute и громкости не меняются. Исходные профили с голосом — личные данные; удаляются удалением их GUID-папок. Откат кода их не удаляет.

Эксперимент расположен в закреплённой ветке `arena/01a0c977-voicekit` отдельным коммитом. Состояние до эксперимента — `aae8a9c`. Отдельная ветка в этой сессии не создавалась. Для отката можно сделать обычный `git revert` коммита лаборатории; без открытия окна старый live DSP работает как раньше.

## Проверка на Windows

1. `dotnet build VoiceKit.slnx -c Release` и `dotnet test tests/VoiceKit.Core.Tests -c Release`.
2. Начать обычную передачу в кабель, открыть лабораторию. Записать принимающую сторону в OBS: лаборатория не должна туда попадать. Попробовать хоткей запуска двигателя при открытом окне — он не должен запустить передачу.
3. На первых 3 с молчать; пройти все этапы. Убедиться в завершении на ~38 с, отсутствии дополнительного захвата после остановки, понятном отчёте.
4. Повторить с тишиной/очень тихой речью/намеренно плохим уровнем (без громкого мониторинга): приложение должно предупреждать, а не уверенно предлагать пресет.
5. Нейтральный A, B +3 st, затем подсказка по целевой медиане. Подготовить одинаковый фрагмент, переключать A/B посреди фразы. Позиция должна продолжаться; не должно быть нескольких плееров одновременно.
6. Поменять слайдер/фрагмент: старое сравнение должно остановиться, применение недоступно до нового расчёта. Проверить стоп, естественный конец и повторный Play.
7. Сохранить профиль, закрыть, открыть его снова. Сверить запись, настройки, отчёт, новый расчёт A/B. Повторное сохранение не должно перезаписывать первый профиль.
8. «Закрыть без применения»: исходные живые эффекты остаются. «Применить»: появляется новый пресет, но микрофон сам не включается.
9. PANIC во время capture, анализа, расчёта и playback; закрытие окна во время worker-задачи; сон Windows; отключение USB. Никакого автопроигрывания/переключения на колонки/автосохранения записи.
10. Несколько открытий/закрытий и повторных записей: устройства должны освобождаться. Проверить 44.1/48 кГц, если доступны.

## Проверки при разработке

Добавлены C# тесты сценария, F0 на синусах/гармониках, тишины/шума/клиппинга, рекомендации, отмены, A/B-рендера, общего курсора, отсутствия аллокаций playback и round-trip WAV/JSON. `CalibrationStore` подключён в тестовый проект как link с NAudio.Core: его managed file IO можно проверить на Linux без WPF/WASAPI.

Здесь .NET SDK недоступен, поэтому **C# сборка/тесты и устройства Windows пока не проверены**. Выполнены синтаксический разбор C#/XAML, 12 JS unit-тестов и 8 браузерных регрессионных тестов. Отдельная численная проверка формулы детектора на синтетических 80/120/220/440 Гц и гармониках дала ожидаемые оценки, шум не дал F0; это не заменяет запуск C# и реальные голоса.
