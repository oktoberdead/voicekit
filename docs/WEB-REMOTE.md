# Веб-пульт: подключение, контракт и проверка

## Где что находится

- `VoiceKit.Remote`: Kestrel, pairing, HTTP endpoints, встроенные статические ресурсы.
- `VoiceKit.Remote/wwwroot`: vanilla HTML/CSS/ES modules без React, сборщика, CDN и внешних шрифтов.
- `VoiceKit.Core/EffectControl.cs`: валидируемый точечный патч пяти эффектов и модель состояния.
- `VoiceKit.Windows/MainWindow.Remote.cs`: перенос запросов на UI thread, запуск/остановка из вкладки «Телефон».
- `tools/preview-web.mjs`: **только UI-симулятор**, не сервер для управления Windows-звуком. Постоянная надпись «Демонстрация» отличает его от настоящего пульта.

Порт по умолчанию 8765, настраивается в Windows-панели. Kestrel слушает доступные интерфейсы; ограничение доступа по профилям сети задаётся брандмауэром Windows. Телефон и ПК должны иметь доступ друг к другу: гостевой Wi-Fi/AP isolation и VPN могут блокировать локальные подключения. `127.0.0.1` пригоден только для браузера на самом ПК. Если LAN-адрес изменился, выключи/включи веб-пульт для обновления списка.

## API v1 (первый минимальный контракт)

Все API-ответы имеют `Cache-Control: no-store`. Сервер не включает CORS. Токен передаётся только заголовком `X-VoiceKit-Token`, не query string. Тела запросов ограничены 4 КиБ, ожидание операции на UI — 5 секунд; отдельной операции запуска аудио и сброса PANIC нет.

### `POST /api/pair`

```json
{ "code": "12345678" }
```

Успех: `{ "token": "…" }`. Неверный код: 401, больше 10 попыток в минуту суммарно: 429 с `Retry-After: 60`. Код в примере не настоящий; текущий код доступен только в окне приложения. Код и токен генерируются при каждом старте сервера. Сопряжённые браузеры этого запуска используют общий случайный токен, отзыв выполняется для всех сразу перезапуском сервера; отдельного списка устройств пока нет.

### `GET /api/state`

```json
{
  "revision": 12,
  "engine": { "running": true, "panic": false, "chainEnabled": true, "microphoneMuted": false },
  "effects": {
    "pitch": { "enabled": true, "semitones": -3 },
    "robot": { "enabled": false, "hz": 70, "mix": 0.8 },
    "echo": { "enabled": true, "delayMs": 280, "feedback": 0.3, "mix": 0.25 },
    "reverb": { "enabled": false, "size": 0.55, "mix": 0.25 },
    "wobble": { "enabled": false, "minSemitones": -2, "maxSemitones": 2, "rateHz": 3 }
  }
}
```

Revision монотонно увеличивается при обнаружении изменения видимого состояния, не является номером аудиоблока. После нового pairing клиент начинает с чистого состояния.

### `PATCH /api/effects/{pitch|robot|echo|reverb|wobble}`

```json
{ "enabled": true, "parameters": { "delayMs": 400, "mix": 0.35 } }
```

Пример выше — для `echo`. `enabled` и `parameters` опциональны, но пустой патч запрещён. Ответ — полное актуальное состояние. Ошибки параметров/неизвестные JSON-поля: 400; нет сессии: 401; чужой Origin: 403. Применение атомарно: если один параметр неверен, остальные не меняются. Другие эффекты/вокодер/устройства не изменяются.

| Эффект | Параметры |
| --- | --- |
| pitch | semitones −12…12 |
| robot | hz 10…300; mix 0…1 |
| echo | delayMs 20…1500; feedback 0…0.85; mix 0…1 |
| reverb | size 0…0.9; mix 0…1 |
| wobble | minSemitones −12…12; maxSemitones −12…12; rateHz 0.1…12 |

Для `wobble` нижняя граница должна быть ≤ верхней. При изменении диапазона браузер отправляет обе границы в одном патче. Перевёрнутый диапазон возвращает 400 без частичного применения. Эти границы — относительные полутоны, не пороги громкости или частота самого голоса.

API устанавливает `enabled`, а не выполняет неидемпотентный toggle. Последний применённый патч побеждает **для конкретного поля**, не всего пресета. Клиент сериализует записи, объединяет ещё не отправленные параметры, не даёт запоздавшему GET откатить новый revision. Polling сейчас достаточен для пяти эффектов; WebSocket не реализован.

## Ограничения безопасности

- HTTP без TLS: код и токен могут быть перехвачены в недоверенной сети. Никакого port forwarding, публичных туннелей и доступа из интернета.
- На ПК код виден владельцу окна; сайт его не возвращает.
- Pairing ограничен по числу попыток. Авторизованный клиент всё равно считается доверенным; это не hardened публичный сервис.
- Файлы раздаются по точному allowlist из embedded resources, не из текущей директории и не из пользовательской библиотеки.
- В URL и логах нет токенов. Браузер хранит токен только в sessionStorage. Перезапуск сервера отзывает все сессии.
- Никаких запросов разрешения на микрофон/камеру, передачи звука, внешних скриптов и аналитики.

## Разработка UI без Windows

Нужен Node.js 22. Для просмотра **именно симулятора** достаточно:

```sh
npm run preview:web
```

Открой `http://localhost:3000` на той же машине или сетевой адрес машины. Preview слушает `0.0.0.0`, допускает proxy host и использует только относительные API URL. Код demo `12345678`, вход автоматический, аудио не обрабатывается. В настоящий Windows-пульт эти demo-код/сервер не входят.

```sh
npm ci
npm run test:web
npx playwright install chromium
npm run test:browser
```

В Linux могут понадобиться системные библиотеки: `npx playwright install --with-deps chromium`. Для уже установленного тестового Chromium можно задать `CHROMIUM_EXECUTABLE`. `playwright.config.mjs` сам поднимет/остановит preview либо использует уже запущенный локальный экземпляр.

`dotnet test tests/VoiceKit.Core.Tests -c Release` дополнительно проверяет C#-валидацию, изоляцию вокодера, pairing и HTTP endpoints настоящего Kestrel. Эти тесты требуют .NET 10 SDK. Браузерные тесты работают с симулятором, поэтому не заменяют тест связки WPF + Kestrel на Windows.

## Что проверено при реализации

- 12 JS-тестов: объединение/очерёдность записей, ревизии, неотправленные жесты, сброс сессии, throttle.
- 8 Chromium-сценариев: разделение зон карточки, второй пульт, слайдеры, disconnect/reconnect, pairing, PANIC, CSP, клавиатура и ширины 320/390/768 px.
- C#/XAML прошли синтаксический разбор. Новый C# host и интеграция с WPF **ещё не собраны/не запущены в среде разработки**, потому что здесь нет доступного .NET SDK. Проверка на Windows обязательна; проверки нового DSP-воббла на Windows тоже обязательны.
